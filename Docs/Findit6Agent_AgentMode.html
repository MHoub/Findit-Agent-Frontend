Agent Mode

AI-driven information retrieval from large data collections - without prior indexing or vectorization. Agent Mode is primarily intended for supported external AI providers or exceptionally large local models running on correspondingly powerful hardware. Your original files remain local; only material selected for AI analysis is transmitted as machine-readable text when an external provider is used.

This page is more than documentation.
It also serves as a direct reference to the instruction files that control Agent Mode. The linked Markdown files are the actual working instructions used by Findit6Agent during research. You can open them directly from this page and, where appropriate, adapt them to your own archive and workflow.

Most core instruction files should normally remain unchanged; Agent_User_Rules.md is specifically intended for your own archive-specific rules and additions.

To edit a Markdown file, copy its link and open the file with your preferred text editor.

How Agent Mode works

In Agent Mode, a capable AI model controls the research process autonomously. It receives the Findit6 search capabilities, the configured search space and detailed operating instructions.

The Agent can perform searches across the complete configured data collection, refine previous result lists, request Context Excerpts, read complete documents, preserve findings in a Ledger and continue researching until it considers the evidence sufficient.

User question→Research mode→Findit6 searches→Evidence→Ledger→Final synthesis

The general operating rules and communication rules apply throughout Agent Mode research.

Knowledge or Statistic? The Agent decides

At the beginning of every Agent Mode research task, the AI determines which type of research the user's question requires. The decision is made automatically and then activates one of two dedicated research briefings.

KNOWLEDGE

Knowledge research

Used when the goal is to find, understand, compare and synthesize information from the most relevant documents.

The Agent may follow several research branches, inspect source documents in detail and combine evidence into a supported narrative answer.

Agent_01_Briefing.md
STATISTIC

Statistic research

Used when the task requires systematic evaluation of a document population - for example counting, classifying, grouping, comparing or aggregating cases.

The workflow emphasizes completeness, explicit handling of unresolved cases, deduplication and deterministic arithmetic where numerical results are required.

Agent_01_StatisticBriefing.md

Both modes use the same Findit6 search engine. The difference is the research contract: Knowledge aims at a well-supported synthesis; Statistic aims at a systematic evaluation of an explicitly defined population.

User-specific archive rules

After the research mode has been selected and the matching briefing is active, the Agent also receives your archive-specific rules. These rules can describe patterns that only you know - for example naming conventions, recurring project structures, characteristic document types, abbreviations or ways in which particular information can be recognized.

Research Ledger

During Agent Mode research, Findit6Agent maintains a compact external Ledger containing the task-relevant information already established from the documents examined by the AI.

A Ledger entry is tied to the complete original file path. It preserves a compact record of the facts extracted from that file. If the same source is encountered again later, newly established information can be added to the existing entry.

The Ledger is not hidden AI memory.
Every Ledger maintained by Findit6Agent is also written to the current Session Workspace as a normal text file ending in .ledger.txt. It can be opened and inspected after the research has finished.

In Knowledge research, the Ledger acts as persistent research memory. In Statistic research, the same structure additionally provides the systematic basis for classification, deduplication, aggregation and exact numerical evaluation.

Large source texts or Context Excerpts do not need to remain permanently in the AI conversation after their useful information has been preserved. If a removed source later becomes important again, the Agent can request the complete document again or recreate Context Excerpts with another search.

Transparent and reproducible: the Session Workspace

For every research session, Findit6Agent creates a dedicated Session Workspace. Depending on the workflow, it contains:

  • Findit6 .fil result lists;
  • generated Context Excerpts;
  • files or machine-readable exports examined by the Agent;
  • Ledger files ending in .ledger.txt;
  • and a detailed software log.

The visible protocol and the Session Workspace together make the research process inspectable and reproducible. Previous hitlists remain useful search populations and can be reused during the same research session.

After a search has started, the current Session Workspace can be opened directly by clicking the small folder icon on the right below the large text box. By default, Session Workspaces are deleted automatically after two weeks. This retention period can be changed, and workspaces that should remain available permanently can be preserved.

Search and source handling

The complete Findit6 search syntax available to the Agent is defined in the search syntax instruction.

Agent_02_Syntax.md

Findit6 performs deterministic retrieval. The Agent decides which population to search and how to interpret the results.

FullSearch

A FullSearch scans the complete configured search scope and is normally used to establish a new candidate population.

HitlistSearch

A HitlistSearch searches only inside the files contained in an existing Findit6 result list. It is therefore usually extremely fast and can be used for narrowing, filtering or investigating another aspect of an already established population.

Context Excerpts and complete files

Context Excerpts expose compact passages around actual search occurrences across many files. Complete documents are requested when the Agent needs fuller context or must resolve a specific uncertainty.

Guided Mode and Agent Mode

Guided Mode

The research process is divided into controlled individual steps. Query construction, semantic reranking, document evaluation and synthesis are guided by dedicated Markdown instructions.

This is especially useful for local AI models with limited context windows and for users who want maximum control over each stage.

Agent Mode

The AI controls the complete research loop autonomously. It decides which searches to perform, which result lists to refine, which sources to inspect and when the available evidence is sufficient.

The automatic Knowledge/Statistic decision and the persistent Ledger allow much longer and more structured autonomous investigations.

Agent Mode, local AI and Guided Mode

Agent Mode is currently intended primarily for very capable non-local AI models. The Agent must independently plan retrieval strategies, operate Findit6 iteratively, evaluate search populations and decide when further research is required. Local models - even in the approximate 70B size range - are generally not yet reliable enough to perform this complete strategic workflow autonomously.

Running Agent Mode locally may therefore become practical only with exceptionally large language models on correspondingly powerful local hardware.

For local research, Findit6Agent provides Guided Mode. Instead of asking one model to control the complete research process autonomously, Guided Mode divides the task into many smaller, clearly defined processing steps. It additionally uses a local semantic reranker and Python-based processing where required.

Guided Mode requires the complete Findit6Agent Suite.
The Guided workflow is available only when the additional components required for it - including the reranker and Python environment - are installed. Agent Mode can be used independently with supported external providers.

For details about the local step-by-step workflow, see Findit6AgentGuidedMode.html.
